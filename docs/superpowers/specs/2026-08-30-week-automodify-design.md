# 機房月檢查表 星期自動填寫工具 — 設計文件

日期：2026-08-30

## 一、問題與目標

機房狀態月檢查表每個月都要人工調整「星期」欄，因為每月一號落在星期幾都不同、月份天數也不同（28/29/30/31），還要判斷哪幾天是假日、假日整列的檢查項目要填 `-`。這件事規則完全固定卻只能手動做，容易漏、容易錯。

本工具把這件事變成：選年月 → 拖入檔案 → 確認預覽 → 下載。

**定位**：使用者實際的工作需求已可由 Claude 官方 Office 增益集解決，本專案定位為練手與離線備援，因此選型優先考慮「家中可開發、可測試」。

## 二、技術選型

**單一自足 HTML 檔（純前端，離線）**

一個 `.html` 檔，雙擊用瀏覽器開啟，所有函式庫內嵌在檔案內，不連 CDN、不開 server、不安裝任何軟體、不產生執行檔。

| 方案 | 結論 | 原因 |
|---|---|---|
| 單一自足 HTML | **採用** | 零安裝零網路，家中無 Office 也能完整開發測試 |
| VBA 巨集 | 排除 | 使用者家中電腦完全沒有 Microsoft Office，無開發測試路徑 |
| Python 打包 exe | 排除 | 公司採白名單式軟體管控，產生 exe 風險最高 |

## 三、需求規格

### 表格結構（已確認）

- **直排**：每一天一列，日期欄與星期欄在左側，右側為各檢查項目欄
- **星期寫法**：單字 `一 二 三 四 五 六 日`
- **格式**：Excel `.xlsx` 與 Word `.docx` 兩種都要支援

### 寫入規則

| 情境 | 日期欄 | 星期欄 | 檢查項目欄 |
|---|---|---|---|
| 平日 | 寫入 1~N | 寫入對應星期 | **清空**（見下方文字內容警示） |
| 假日（六日、國定假日） | 寫入日期 | 寫入對應星期 | **全部填 `-`** |
| 補班日（六日但要上班） | 寫入日期 | 寫入對應星期 | 視同平日，不填 `-` |
| 超出當月天數的列 | 清空 | 清空 | 清空 |

「檢查項目欄」定義為**日期欄與星期欄以外的所有欄位**，含備註欄。

**文字內容警示**：檢查欄平常填的是 V／X 這類記號，重填不損失資訊；但備註欄可能寫有真正的文字。因此預覽時須掃描即將被清空的儲存格，**凡內容不是單一記號（V、X、v、x、○、✓、✗、-、空白）者，一律在預覽中醒目標示並列出原文**，讓使用者在按下轉檔前看見自己將失去什麼。這是提示而非阻擋，使用者確認後仍照常清空。

### 年月來源

畫面上選年月，預設帶入當月。不從檔案標題讀取。

### 標題年月同步

工具會一併把文件中的年月文字改成所選年月。

- **偵測**：以正規式掃描全文（Excel 含儲存格與頁首頁尾，Word 含內文與頁首頁尾），尋找 `([0-9]{2,4})[ ]*年[ ]*([0-9]{1,2})[ ]*月` 形式的文字
- **紀年判斷**：擷取到的年份小於等於 200 視為民國年，大於等於 1911 視為西元年
- **格式沿用**：改寫時完整沿用原本的寫法，包含紀年制（民國／西元）、是否補零（`8月` 對 `08月`）、以及年月之間有無空白。目標是只換數字，不改變外觀
- **逐一確認**：文件中可能有多處年月（標題、頁尾、簽核欄）。預覽畫面列出**每一處**找到的位置與改寫前後對照，預設全部勾選，可個別取消
- **找不到**：不視為錯誤，靜默跳過並在預覽中註明「未偵測到年月文字」

### 檔案處理

- 一次處理一個檔案
- **原檔永不覆蓋**，輸出新檔名（如 `原檔名_115年09月.xlsx`）
- 只改日期欄、星期欄、檢查項目欄的值與經你確認的年月文字，其餘儲存格、格式、公式、合併儲存格一概不動

## 四、架構

四層，由下而上：

| 層 | 職責 | 依賴 |
|---|---|---|
| **日曆核心** | 給年月 → 產出 `[{日, 星期, 是否假日, 假日原因}]` | 無，純函式 |
| **假日資料** | 取得台灣行事曆：線上 → 內建 → 純計算，三層遞降 | 無 |
| **Excel 轉接** | 讀寫 `.xlsx` | SheetJS |
| **Word 轉接** | 解 `.docx` zip → 改 `document.xml` 表格 → 重新打包 | JSZip |
| **UI** | 選年月、月曆顯示、拖放、欄位確認、預覽、下載 | 無 |

日曆核心零依賴、可獨立單元測試。Excel 與 Word 兩個轉接層互不相干，一邊出問題不影響另一邊。

## 五、假日資料來源

採**三層遞降策略**，有網路就用最新資料，沒網路也能正常運作。

| 層級 | 來源 | 涵蓋 | 觸發時機 |
|---|---|---|---|
| 1. 線上 | `cdn.jsdelivr.net/gh/ruyut/TaiwanCalendar/data/<年>.json` | 國定假日、彈性放假、補假、補班日 | 選定年月時嘗試抓取 |
| 2. 內建 | 打包進工具的 2024–2027 年資料 | 同上 | 線上抓取失敗時 |
| 3. 計算 | JavaScript `Date` 推算 | **僅六日**，無國定假日 | 該年度連內建資料都沒有時 |

畫面必須明確標示目前用的是哪一層，例如「已取得 2026 年最新假日資料」或「使用內建資料（更新於 2026-08）」或「⚠ 2031 年無假日資料，僅依六日判斷」。使用者要能一眼知道判斷依據可不可信。

**線上來源已實測驗證**（2026-08-30）：

- 回應標頭含 `access-control-allow-origin: *`，因此 `file://` 開啟的頁面也能成功 fetch，不受 CORS 阻擋
- 資料格式為 `{date, week, isHoliday, description}`，`week` 欄位直接就是「一二三四五六日」單字，與本工具需求完全一致
- 補班日表達方式：`week` 為六或日但 `isHoliday` 為 `false`（2026 年無補班日，2024/2025 年有）
- 2024、2025、2026、2027 年資料皆可取得

**依賴風險**：該來源為社群維護的 GitHub 專案（資料源自政府開放資料），並非政府官方 API。公司防火牆也可能阻擋 jsDelivr。因此第 2 層內建資料是必要的保底而非備品，不可省略；若該專案停止維護，內建資料仍可運作，並可替換來源。

**星期的計算方式**：優先採用資料中的 `week` 欄位，而非自行推算，以避免時區與跨日誤差。僅在第 3 層才由程式推算。

畫面上顯示**當月月曆**，假日標紅、補班日標藍、平日不標，讓使用者在轉檔前一眼確認判斷是否正確。若遇颱風假等臨時狀況，可在月曆上直接點選切換某天的假日狀態。

## 六、欄位偵測策略

沒有實體範例檔可參照，因此不能寫死欄位位置。採**偵測 + 手動退路**：

1. 掃描表頭列，尋找含「日期」「日」的欄位與含「星期」「週」的欄位
2. 偵測成功 → 直接使用，並在畫面上顯示偵測結果供確認
3. 偵測失敗 → 顯示表格前幾列，由使用者手動指定哪欄是日期、哪欄是星期

使用者的手動指定結果記錄在 `localStorage`，下次開啟同結構的檔案自動帶入。

## 七、資料流

```
選年月（預設當月）
  → 顯示當月月曆（假日標紅、補班標藍，可手動修正）
  → 拖入檔案
  → 解析檔案、偵測日期欄與星期欄（失敗則請使用者指定）
  → 掃描文件中的年月文字
  → 【預覽】列出每一列將寫入的內容（假日列明確標示）
         與每一處年月的改寫前後對照
  → 使用者確認
  → 產生新檔並下載
```

**預覽這一關不可省略**。沒有實體範例檔可先驗證，等於是盲寫，必須先看再寫，避免破壞文件。

## 八、錯誤處理

| 情況 | 處理 |
|---|---|
| `.xls` / `.doc` 舊格式 | 明確擋下，提示「請用 Office 另存成 .xlsx / .docx」 |
| 檔案損壞或非 Office 檔 | 顯示具體錯誤，不吞錯 |
| 檔案內找不到表格 | 明確告知，不產生輸出 |
| 找不到年月文字 | 不報錯，預覽中註明未偵測到，其餘照常處理 |
| 欄位偵測失敗 | 不報錯，轉為手動指定流程 |
| 表格列數少於當月天數 | 警告並列出寫不下的日期，讓使用者決定是否繼續 |
| 線上抓取失敗（斷網、防火牆、逾時） | 靜默退回內建資料，畫面標示資料來源，不中斷流程 |
| 所選年月超出內建行事曆範圍 | 警告「該年度假日資料未內建，僅依六日判斷」，仍可繼續 |

## 九、測試策略

**日曆核心採 TDD**，測試案例至少涵蓋：

- 閏年 2 月（29 天）與平年 2 月（28 天）
- 30 天月份與 31 天月份
- 月初落在星期日、月初落在星期一
- 跨年（12 月 → 1 月）
- 國定假日落在平日
- 補班日（週六但需上班）
- 連假（彈性放假）

**端對端測試素材**：使用者手邊無範例檔，因此由開發方產生一份仿真的機房月檢查表（Excel 與 Word 各一）放入 `samples/`，作為實際驗證依據。

測試以 `tests.html` 呈現，雙擊瀏覽器開啟即可執行並看到綠/紅結果，不需要任何工具鏈。

## 十、專案結構與發布

```
src/
  calendar-core.js      日曆核心（純函式）
  holidays-tw.js        假日資料層（線上抓取 + 內建資料 + 純計算 fallback）
  excel-adapter.js      Excel 讀寫
  word-adapter.js       Word 讀寫
  ui.js                 介面
  index.html            開發用進入點
vendor/
  xlsx.full.min.js      SheetJS（本地副本）
  jszip.min.js          JSZip（本地副本）
samples/                仿真測試檔
tests.html              單元測試，雙擊即可執行
dist/
  檢查表星期填寫工具.html   合成後的單一自足檔案
build.js                合成腳本
```

開發時是分開的模組，Git 可正常 diff 與 review。發布時由 build 步驟合成單一 HTML，**build 由開發方執行並將成品 commit 進 repo**，使用者端不需安裝 Node 或任何工具鏈，`git pull` 後直接使用 `dist/` 內的檔案。

## 十一、明確排除的範圍（YAGNI）

- 批次處理多個檔案（一次一個即可）
- 舊版 `.xls` / `.doc` 格式支援
- 假日列標色（只填 `-`，不動格式）
- 線上部署或伺服器
